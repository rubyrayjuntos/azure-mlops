In software engineering, **property-based testing** (such as with Hypothesis or QuickCheck) refers to generating arbitrary inputs to verify that logical invariants hold across code functions.

For infrastructure automation, Terraform declarations, and CI/CD workflows, the equivalent rigorous approach uses **deterministic post-condition assertions** and **state invariant checks**. These are automated verification steps that fail fast if a task leaves the environment or repository in an invalid state.

Below are post-condition invariant assertions for each task in your implementation plan.

## Phase 0 — Identity & Permissions

### Task 1: Grant Subscription `Owner` Role

* **Invariant:** The service principal holds `Owner` at subscription scope.
* **Assertion:**

```bash
az role assignment list \
  --assignee 1f783207-33c9-40c5-ab2d-01a1f1510c8e \
  --scope /subscriptions/5b452321-32fd-4b1c-8bbf-6d69a5a587ad \
  --query "[?roleDefinitionName=='Owner']" -o json | python3 -c "import json,sys; assert len(json.load(sys.stdin)) >= 1, 'Invariant Failed: Owner assignment missing'"

```

### Task 2: Main-Branch Federated Credentials

* **Invariant:** The AD Application registration contains exactly 4 active federated credentials (`main` and `dev`, plain and transitional).
* **Assertion:**

```bash
az ad app federated-credential list --id 4a03064f-784b-4f7b-a429-46fad02549b5 -o json | python3 -c "
import json, sys
creds = {x['name'] for x in json.load(sys.stdin)}
expected = {
    'github-azure-mlops-dev-branch',
    'github-azure-mlops-dev-branch-transitional',
    'github-azure-mlops-main-branch',
    'github-azure-mlops-main-branch-transitional'
}
assert expected.issubset(creds), f'Invariant Failed: Missing credentials: {expected - creds}'
"

```

## Phase 1 — `mlops-templates` Repository Verification

### Task 3: Unpin Self-References

* **Invariant:** `.github/workflows/read-yaml.yml` references the action via `@main` without any commit SHAs.
* **Assertion:**

```bash
grep -q "uses: rubyrayjuntos/mlops-templates/read_yaml_action@main" .github/workflows/read-yaml.yml || (echo "Invariant Failed: Self-reference not updated to @main" && exit 1)

```

### Task 4: Pin Marketplace Actions to Commit SHAs

* **Invariant:** Zero bare or floating major version tags (`@v2`, `@v4`) exist for third-party actions in the target workflows. Every reference uses a 40-character hexadecimal SHA.
* **Assertion:**

```bash
# Must return 0 matches
! grep -E "uses: (azure/login|actions/checkout)@v[0-9]" .github/workflows/*.yml && \
! grep -E "uses: (azure/login|actions/checkout)@[a-f0-9]{1,39}$" .github/workflows/*.yml

```

## Phase 2 — `mlops-project-template` Nested Source Verification

### Task 5: Infrastructure Deployment Workflow (`infrastructure/terraform/github-actions/tf-gha-deploy-infra.yml`)

* **Invariant 1:** Contains `permissions: id-token: write` for OIDC authentication.
* **Invariant 2:** Evaluates `enable_aml_computecluster` as a string boolean comparison (`== 'true'`).
* **Assertion:**

```bash
grep -q "id-token: write" infrastructure/terraform/github-actions/tf-gha-deploy-infra.yml && \
grep -q "enable_aml_computecluster == 'true'" infrastructure/terraform/github-actions/tf-gha-deploy-infra.yml

```

### Task 6: Training Pipeline Workflow (`classical/aml-cli-v2/mlops/github-actions/deploy-model-training-pipeline-classical.yml`)

* **Invariant:** Every job using OIDC reusable workflows explicitly declares `permissions: id-token: write, contents: read`.
* **Assertion:**

```bash
python3 -c "
import yaml
with open('classical/aml-cli-v2/mlops/github-actions/deploy-model-training-pipeline-classical.yml') as f:
    data = yaml.safe_load(f)
for job_name, job in data.get('jobs', {}).items():
    if 'uses' in job and 'rubyrayjuntos' in job['uses']:
        perms = job.get('permissions', {})
        assert perms.get('id-token') == 'write', f'Invariant Failed: {job_name} missing id-token: write'
"

```
